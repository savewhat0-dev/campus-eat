# Campus Eats login and menu image update

## What changed
- Customer login accepts a normal university email address ending in `@bmu.edu.in`; the text no longer suggests `.25bb` is required. Dots in the address are accepted. Customers receive a one-time code and do not create a password.
- Retailer usernames are matched without regard to letter case. Their passwords remain case-sensitive.
- The sign-in dialog checks configuration readiness and shows which Render environment settings are missing. It never displays secret values.
- Student OTP delivery failures point to the Resend API key, verified sender, and Resend delivery log.
- Menu items use 32 generated food photos mapped to their dish category instead of reusing the outlet-banner crop.

## Publish this update
1. Extract `Campus-Eats-Login-Images-Fix.zip`.
2. Upload the extracted contents into the root of the same GitHub repository and branch used by the Render `campus-eat` service, replacing matching files and preserving folders.
3. On Render, use **Manual Deploy → Clear build cache & deploy** (or deploy the new GitHub commit).
4. Keep the existing `DATABASE_URL`, `RESEND_API_KEY`, `EMAIL_FROM`, and `RETAILER_ACCOUNTS` values. Do not paste secret values into GitHub or chat.
5. In the deployed site, open sign-in. If a setup warning appears, fix the named Render environment setting and redeploy.

The configuration status endpoint is `/api/campus/config`; it returns readiness booleans only. Customer email delivery still requires a valid Resend key and an approved sender. Retailer sign-in requires the full five-account hashed JSON generated by the provisioning helper.
